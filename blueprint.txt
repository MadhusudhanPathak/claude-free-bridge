# API Bridge Architecture Blueprint
## Claude Web Interface to Coding Agents

**Version:** 1.0
**Status:** Draft
**Target Environment:** Localhost / Self-Hosted

---

### 1. Local API Server Design

#### 1.1 Framework Selection: FastAPI (Python)

**Why FastAPI:**
- **Async Support:** Native asynchronous request handling is critical for non-blocking I/O operations (Playwright, network calls).
- **Automatic OpenAPI Documentation:** Facilitates debugging of request/response schemas.
- **Type Validation:** Pydantic ensures strict validation of incoming requests from coding agents, catching errors early.
- **Streaming Capability:** Built-in support for Server-Sent Events (SSE) and streaming responses, crucial for a ChatGPT-like experience.
- **Ecosystem:** Robust integration with HTTPX for internal requests.

**Alternative Considered:** Node.js/Express. Rejected due to slightly less robust async handling for heavy browser automation compared to Python's `asyncio` + Playwright.

#### 1.2 Endpoint Structure (Anthropic Compatibility)

To act as a "drop-in" replacement, the middleware must mirror the **Anthropic Messages API** structure.

**Base Path:** `/v1/`

**Primary Endpoint:**
- **POST** `/v1/chat/completions`

**Secondary Endpoints (Optional but recommended for compatibility):**
- **GET** `/v1/models` → Returns a list containing `"claude-3.5-web"` (or a similar identifier) to allow the coding agent to detect the "model".

#### 1.3 Request Schema (Pydantic Model)

The server must accept the standard Anthropic request body.

```python
from pydantic import BaseModel
from typing import List, Optional, Dict, Any

class Message(BaseModel):
    role: str  # "user", "assistant"
    content: str

class ChatCompletionRequest(BaseModel):
    model: str # We will ignore this and map to the current web session
    messages: List[Message]
    stream: Optional[bool] = False
    max_tokens: Optional[int] = 4096  # Web limit
    temperature: Optional[float] = 0.7
    top_p: Optional[float] = 0.9
    # Optional: For internal use to bypass web session limits
    conversation_uuid: Optional[str] = None 
```

**Decision Callout:** We ignore the `model` parameter and map it to the active Claude web session. We keep `max_tokens` to truncate the prompt if necessary to fit the web context window (~200k).

### 2. Session & Browser Automation Layer

#### 2.1 Stack Selection: Playwright for Python

**Why Playwright:**
- **Reliability:** Automatic waiting, web-first assertions, and robust selectors.
- **Stealth:** Better capabilities for evading bot detection compared to Selenium.
- **State Management:** Excellent support for saving/restoring browser contexts (cookies, localStorage, IndexedDB) via `storageState`.

#### 2.2 Session Persistence Strategy

Since login is already implemented, we will leverage the **Browser Context** serialization.

```python
import asyncio
from playwright.async_api import async_playwright, Browser

class SessionManager:
    def __init__(self):
        self.browser: Browser = None
        self.context = None
        self.page = None
        self.is_authenticated = False
        self.state_file = "claude_state.json"

    async def initialize(self):
        playwright = await async_playwright().start()
        # Launch persistent or non-persistent context
        if self.state_file exists:
            self.context = await browser.new_context(storage_state=self.state_file)
        else:
            # Fallback to login (handled elsewhere)
            self.context = await browser.new_context()
        self.page = await self.context.new_page()
        
    async def save_state(self):
        await self.context.storage_state(path=self.state_file)
```

#### 2.3 Handling the 5-Hour Session Refresh Cycle

Claude's web interface invalidates the session roughly every 5 hours or on browser fingerprint changes.

- **Detection:** Intercept network responses. If a request returns a `401` or redirects to `/login` or `/signup`, the session is dead.
- **Re-authentication Trigger:** If expiration is detected, the middleware will:
  1. **Pause the queue** (see Section 4).
  2. Trigger the re-authentication flow (already implemented).
  3. **Wait** for a successful "200 OK" on the main conversation page.
  4. **Update** `state_file`.
  5. **Resume** the queue.

**Critical Flag:** This is a **fragile dependency**. If Claude changes their HTML structure or login flow, this step breaks.

### 3. Request Forwarding Pipeline

#### 3.1 Flow Diagram (ASCII)

```
+----------------+     +-----------------+     +-----------------+     +-------------------+
| Coding Agent   | --> | FastAPI Router  | --> | Prompt Wrapper  | --> | Playwright Context|
| (POST /v1/... )|     | (Parse Request) |     | (Transform)     |     | (Page.goto)       |
+----------------+     +-----------------+     +-----------------+     +-------------------+
                                                                               |
                                                                               v
+----------------+     +-----------------+     +-----------------+     +-------------------+
| Coding Agent   | <-- | Response Parser | <-- | Extract Content | <-- | Claude Web UI     |
| (Stream/JSON)  |     | (SSE or JSON)   |     | (DOM/Network)   |     | (Process Prompt)  |
+----------------+     +-----------------+     +-----------------+     +-------------------+
```

#### 3.2 Step-by-Step Translation

1. **Incoming Request:** Receive `ChatCompletionRequest`.
2. **Conversation Context:** The middleware must maintain a "thread" ID. If the coding agent sends `conversation_uuid`, we use it. Otherwise, we create a new chat session on Claude.
3. **Browser Navigation:**
   - If new chat: Navigate to `https://claude.ai/new`.
   - If existing: Navigate to `https://claude.ai/chat/{conversation_uuid}`.
4. **Prompt Injection:**
   - Locate the `textarea` (selector: `div[contenteditable="true"]`) inside the prompt input area.
   - Insert the `messages[-1].content` (the latest user message).
   - **Context Injection:** Combine all previous `messages` into a single formatted prompt (e.g., "Previous context: ...") if the coding agent does not manage the UUID.
5. **Trigger Submission:**
   - Click the "Send" button or simulate an `Enter` keypress.
6. **Wait for Response (Hybrid Approach):**
   - **Network Interception (Preferred):** Use Playwright's `page.route` to intercept the `POST` request to `*.anthropic.com/api/chat`.
   - **DOM Polling (Fallback):** Wait for the `.message-content` elements to update and compare the new addition.

#### 3.3 Streaming vs. Non-Streaming

- **Non-Streaming:** Wait for the "Stop generating" button to disappear or the final SSE event to be intercepted. Aggregate the full text and return it.
- **Streaming:** If `stream: True` in the request:
  1. Open an SSE connection back to the coding agent.
  2. As chunks arrive from Claude's internal SSE stream (intercepted via `page.route`), forward them to the coding agent **immediately**.
  3. This requires translating Claude's internal chunk format to the Anthropic SSE format.

### 4. Concurrency & Queue Management

#### 4.1 The Single-Session Constraint

Claude Web is designed for a single user. Running multiple parallel requests simultaneously will cause:
- Race conditions in the input field.
- Session state corruption.
- Browser crashes.

#### 4.2 Queuing Strategy

We implement a **FIFO (First-In-First-Out)** queue with a single worker processing one request at a time.

```python
import asyncio
from asyncio import Queue

class RequestQueue:
    def __init__(self):
        self.queue: Queue = asyncio.Queue()
        self.is_processing = False
        
    async def enqueue(self, request_data, response_channel):
        await self.queue.put((request_data, response_channel))
        if not self.is_processing:
            asyncio.create_task(self.worker())
            
    async def worker(self):
        self.is_processing = True
        while not self.queue.empty():
            request, channel = await self.queue.get()
            try:
                result = await process_with_browser(request)
                await channel.send(result)
            except Exception as e:
                await channel.send_error(e)
            finally:
                self.queue.task_done()
        self.is_processing = False
```

#### 4.3 Priority & Timeouts

- **Priority:** Not currently needed. If implemented, allow "Ping" requests (health checks) to skip the queue.
- **Timeout:** Each request has a `timeout` of 300 seconds (5 minutes). If the Claude UI hangs, the request is dropped, and the browser session is forcefully refreshed to prevent memory leaks.

#### 4.4 Error Handling Matrix

| Error Type | Action |
| :--- | :--- |
| **Session Expired (401)** | Pause queue > Re-authenticate > Resume queue > Retry request. |
| **Rate Limiting (429)** | Wait 60 seconds (exponential backoff) and retry. |
| **UI Change (Selector not found)** | **Critical Failure.** Alert admin to update selectors. Stop queue. |
| **Network Timeout** | Reload browser context (without re-auth) and retry. |

### 5. Response Normalization

#### 5.1 Parsing Strategy

The response from Claude Web is typically delivered via **Server-Sent Events (SSE)** in the following format:

```
event: content_block_delta
data: {"type":"content_block_delta","index":0,"delta":{"type":"text_delta","text":"Hello"}}
```

**Extraction:** We intercept these SSE messages using Playwright's network monitoring.

```python
def parse_claude_chunk(raw_data: dict) -> dict:
    # Map Claude Web format to Anthropic Messages API format
    if raw_data.get("type") == "content_block_delta":
        return {
            "id": "chatcmpl-web",
            "object": "chat.completion.chunk",
            "choices": [{
                "index": 0,
                "delta": {"content": raw_data["delta"]["text"]},
                "finish_reason": None
            }]
        }
    elif raw_data.get("type") == "message_stop":
        return {
            "choices": [{
                "finish_reason": "stop"
            }]
        }
```

#### 5.2 Cleaning Data

- **UI Artifacts:** Claude sometimes outputs Markdown that includes UI buttons or "Copy" artifacts in the raw HTML. Since we intercept the network payload, we receive **raw text**, avoiding the need for HTML cleaning.
- **Token Counting:** The Web UI does not return token counts. We calculate this client-side using `tiktoken` (if needed for tracking) or simply set `usage` to `null` in the response.

#### 5.3 Final Response Mapping

We construct a response matching the Anthropic API specification.

```json
{
  "id": "msg_web_xyz",
  "model": "claude-3.5-web",
  "object": "chat.completion",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "[CLEANED RESPONSE TEXT]"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 0,
    "total_tokens": 0
  }
}
```

Create a `config.yaml` or `.env` file for the developer.

```yaml

  refresh_interval_hours: 4.5  # Trigger refresh before the 5-hour limit

  max_concurrency: 1
  retry_attempts: 3
```

Coding agents should be configured to point to the middleware rather than the official API.

Implement a `/health` endpoint to allow coding agents or Docker orchestrators to verify the middleware is running and the Claude session is active.

async def health_check():

### 7. Critical Fragile Dependencies (Red Flags)

**Warning:** The following components are highly sensitive to changes on Claude's side and require monitoring:

1. **DOM Selectors:**
   - `textarea` or `div[contenteditable="true"]` for input.
   - The "Send" button class/ID.
   - The "Stop generating" button class/ID.
2. **Network Endpoints:**
   - The path to the SSE streaming endpoint (e.g., `/api/chat`).
   - The format of the `conversation_uuid` in the URL structure.
3. **Authentication Cookies:**
   - The name of the session cookie (e.g., `__Secure-session`).
   - The login flow redirect pattern.

**Mitigation Strategy:** Implement a "Selector Health Check" routine that runs every hour. If a selector fails to resolve, the middleware logs a critical error and triggers a notification to the user (via console logs).

### 8. Summary of Success Criteria

- **Connection:** Coding agent sends request to `http://localhost:8080/v1/chat/completions`.
- **Proxy:** Middleware translates request, routes through Playwright to `claude.ai`.
- **Response:** Claude's response is stripped of UI artifacts and returned as a valid Anthropic Chat Completion object.
- **Resilience:** Session expiry triggers automatic re-authentication without crashing the queue.

**Next Steps:** Implementation of the `RequestQueue` and `NetworkInterceptor` classes, followed by integration testing with Cursor IDE.
